# 首发实验室 / Starting Five Lab

无需 API Key、无需安装依赖的 NBA 球迷小游戏。两套球员池：80 位现役球员按 2026–27 赛季名单与开季表现制作；80 位历史球星取各自在可获取 NBA 2K 版本中的最高总评。选秀按控球后卫 → 得分后卫 → 小前锋 → 大前锋 → 中锋依次进行，每个位置出现 5 个可逐个开启的盲盒。五人确定后可加入东部或西部，替代该分区现役评分最弱球队，并与由 2026–27 现役球员能力值换算的 29 支对手模拟一个完整赛季。另有双人竞拍模式：两名玩家各 20 元，公开竞拍 10 名历史球星，盲拍、补位、自由排阵后打七场四胜。

## 本地启动

直接试玩：打开交付的 `首发实验室.html` 即可，无需安装或联网。该文件包含页面、样式、球员池、球员头像和模拟引擎。文件模式下，部分浏览器可能不允许保存历史记录，但仍可模拟赛季。

修改源码后运行：

Windows 可直接双击 `启动服务器.bat`。也可以在终端运行 `node server.mjs`，然后打开 http://127.0.0.1:4173 。赛季模式和竞拍模式都通过同一个本地服务器提供；竞拍联机使用房间码，服务器会监听局域网地址。运行 `npm test` 验证赛季引擎、竞拍状态机、盲拍隐藏、免费补位和七场四胜。安装了 npm 时也可使用 `npm start`。

## 文件

- `dist/players.js`：160 位球员的现役 / 历史池及评分；历史球员包含 2K 总评、2K 版本、卡片球队与属性映射来源。
- `dist/teams.js`：2026–27 赛季 30 支对手球队、东西部分区、战绩，以及由现役球员评分换算的强度 / 节奏。
- `dist/league-players.js`：456 名有 2026–27 出场样本球员的运行时评分，用于生成对手球员数据和赛季奖项。
- `dist/auction.html`、`dist/auction.css`、`dist/auction.js`：竞拍模式的页面与交互，共享霓虹主题。
- `dist/auction-data.js`：80 名历史球员的身高、巅峰球队与盲拍展示字段。
- `dist/auction-core.js`：竞拍状态机、免费补位、流拍重拍、自由排阵和七场四胜系列赛。
- `auth-core.js`：密码哈希、签名会话 token 与 cookie 工具。
- `Dockerfile`、`docker-compose.yml`、`Caddyfile`、`render.yaml`：公网部署与 HTTPS 配置。
- `server.mjs`：静态页面、账号 API、房间码 API 与局域网服务。
- `dist/engine.js`：确定性随机数、抽卡、阵容搭配、完整赛季引擎、个人数据和奖项评选。
- `dist/app.js`：逐位置盲盒抽选、交互、战报和最近五次本地记录。
- `dist/index.html`、`dist/style.css`、`dist/theme-neon.css`、`dist/theme.js`：网页、响应式样式与双主题切换。
- `dist/photos.js`、`dist/assets/players/`：160 张球员头像及本地映射。

## 选秀流程

1. 在首页点击“开始抽选”，或在选秀室点击“开始抽选”。默认使用现役球员池和东部；可先在选秀室切换球员池与分区。
2. 位置顺序固定为 PG → SG → SF → PF → C。每个位置会显示 5 个盲盒，盲盒不会提前暴露姓名或评分。
3. 点击盲盒逐个翻开，查看球员姓名、总评、进攻、防守、投射等信息；点击“选择此人”确定该位置。
4. 选中后自动进入下一个未完成位置。顶部进度条可回到已完成位置更换球员；选中的旧盲盒会保持可见。
5. 五个位置全部确定后，首发五人会在深绿色选秀面板中汇总，页面底部出现“开始模拟赛季”按钮。
6. “重新抽卡”会从控球后卫重新开始；切换球员池会清空本轮选择并回到设置状态，切换分区不会破坏当前阵容。

## 账号与登录

房间码联机需要先注册或登录；单机 AI 不需要账号。

- 注册：用户名 3–20 位中文、字母、数字或下划线，密码至少 6 位。
- 手机号注册：昵称仍用于房间显示，可额外填写 11 位手机号；之后可使用“用户名或手机号 + 密码”登录。手机号只作为登录标识，当前不发送短信验证码。
- 密码使用 Node.js `scrypt` 加盐哈希，服务器只保存 salt 和哈希，不保存明文密码。
- 登录成功后写入 HttpOnly、SameSite=Lax 的 7 天会话 cookie；退出登录会清除。
- 手机号会与账号一起保存在 `data/users.json`，接口只返回脱敏号码。
- 账号数据保存在服务器当前项目的 `data/users.json`，签名密钥保存在 `data/auth-secret`，两者已加入 `.gitignore`。
- 在线创建/加入房间会要求登录有效；房间操作同时校验账号与房间内玩家身份。
- 账号系统是本地服务器账号，不是 GitHub OAuth，也不依赖第三方登录。
- 单文件 `竞拍模式.html` 只能单机 AI；登录和房间码需要运行 `node server.mjs`。

## 竞拍模式

从首页右上角的“竞拍模式”进入，或直接打开 `dist/auction.html`。

- 两名玩家默认各 20 元，房主可选择 20 / 30 / 50 元预算；10 名历史球星随机顺序拍卖，每队最多 5 人。
- 公开轮流加价，起拍 1 元，可以一次加多档；放弃当前球员后，下一件拍品可以重新出价。
- 不强制留钱。一队买满 5 人后，剩余球员免费归另一队；一队花光预算时，另一队先从剩余池免费挑选，剩下的补给花光预算的一方。
- 双方都没钱时免费补齐。10 件拍品后两队都没满 5 人，则继续轮流拍流拍球员；一整轮无人出价后免费补齐。
- 信息模式：
  - 全公开：姓名、头像、总评、位置、身高（cm）、巅峰球队和五项能力。
  - 身高盲拍：只显示身高（cm），其余信息隐藏。
  - 球队盲拍：只显示巅峰球队与年代，其余信息隐藏。
  - 盲拍期间已买球员也保持隐藏，双方阵容完整后统一揭晓。
- 竞拍后自由安排 PG / SG / SF / PF / C；球员自然位置与攻防属性不变。双方提交后模拟七场四胜。
- 单机模式可切换简单 / 普通 / 困难 AI；联机模式通过房间码。创建房间后把 5 位房间码发给朋友，另一位玩家在首页输入加入，房主点击开始。
- 联机状态通过 SSE 实时推送，出价、开始、补员和排阵无需轮询。EventSource 会自动重连。
- 房间和账号会持久化到 `data/`；服务器重启后，已登录玩家可以恢复房间。浏览器同时保存房间会话，刷新页面会自动回到原房间。
- 房间码联机需要运行 `node server.mjs`。服务器监听 `0.0.0.0`，局域网内其他设备可使用终端打印的 LAN 地址；公网联机需要自行部署并开放端口。
- 独立文件 `竞拍模式.html` 内嵌 80 张历史头像，支持单机 AI；房间码联机需要服务器版本。

## 主题

赛季模式和竞拍模式右上角都有“✦ 霓虹主题 / ☀ 米白主题”切换按钮。

- 默认仍是原先的米白纸感主题。
- 暗黑霓虹主题使用黑绿底色、荧光绿边框与橙色主按钮。
- 选择会保存到浏览器 `localStorage`，两个页面共用同一个主题状态。
- 单文件版也已内嵌两套样式，无需额外文件。

## 公网部署

在线房间必须运行 Node 服务器，不能只用 GitHub Pages。HTTPS 建议交给反向代理或托管平台处理。

### Docker + Caddy

1. 准备一台云服务器和域名，将域名 A 记录指向服务器。
2. 安装 Docker 和 Docker Compose。
3. 在项目目录创建 `.env`：

```text
DOMAIN=game.example.com
```

4. 启动：

```bash
docker compose up -d --build
```

Caddy 会自动申请和续期 HTTPS 证书。房间与账号保存在 Docker 卷 `nba-data` 中。

### Render / Railway / Fly.io

- 构建命令：不需要额外构建，直接运行 `node server.mjs`
- 启动命令：`node server.mjs`
- 健康检查：`/healthz`
- 需要持久化磁盘，并将环境变量 `DATA_DIR` 指向该磁盘
- 平台会自动提供 HTTPS

仓库附带 `Dockerfile`、`docker-compose.yml`、`Caddyfile`、`render.yaml` 和 `.env.example`。

## 球员池

- **现役球星 · 2026–27**：80 人，16 人 / 位置。名单、球队与球衣号码按 2026 年 11 月 9 日 ESPN 公开名单快照；能力值使用当时可见的 2026–27 开季表现制作，之后发生的交易、伤愈和状态变化不会自动更新。
- **历史巅峰 · 全时代**：80 位跨时代代表球星，16 人 / 位置。每人取在可获取 NBA 2K 版本中的最高总评，覆盖 2K16–2K21、2K25 All-Time / Current 与 2K27 Current。卡片显示 `球衣号 / 2K版本`，总评徽章显示该 2K 最高总评；悬停可看 2K 卡来源、球队、NBA 巅峰年份和属性映射版本。攻防投传板五项由 2K 属性映射并校准，不是逐项照搬。雷吉·米勒、查尔斯·巴克利因可用 2K 数据缺失使用人工回退，卡片标注 `MANUAL`。
- 历史池不是完整 2K 数据库，未覆盖 2K11–2K15 等版本；因此“最高”指所用数据集中可获取的最高总评，不宣称穷尽全部 2K 历史。2K25 All-Time 是 2K25 内的全时代卡；部分传奇的最高值来自该卡，而不是他们巅峰赛季的当季卡。

两套池子的头像、能力尺度和抽卡完全独立。

## 对手球队与分区

- 玩家在开赛前选择加入**东部**或**西部**；系统会移除该分区现役评分最低的球队，由“首发实验室”替代，另一分区保持 15 队不变。
- 其余 29 支对手的球队强度来自 **2026–27 现役球员能力值**，不再由战绩或净胜分直接决定：
  1. 按现役池完全相同的五项公式，给每名有 2026–27 出场数据的球员生成进攻、防守、投射、组织、篮板与总评。
  2. 每队按总评取前 9 人轮换；权重为 `1, 1, 1, 1, 1, 0.62, 0.52, 0.44, 0.36`，出场可用性 = `min(1, 出场数 / 9)`。
  3. 球队评分 = 轮换球员总评的可用性加权平均，再按 30 队分布做 z-score，映射为 `clamp(87 + z × 5, 68, 99)`。
- 当前快照共 522 名名单球员，其中 456 名有 2026–27 出场样本并参与强度计算；66 名无出场样本的球员不计入轮换。现役池 80 人的评分则直接复用卡片上的精确能力值。
- 球队名称、分区、当前战绩与比赛节奏仍来自 ESPN NBA 2026–27 standings（2026-11-09）；战绩只用于展示，比赛节奏 = `(场均得分 + 场均失分) / 2`。
- 当前快照最弱队：东部为芝加哥公牛（强度 75.8），西部为犹他爵士（强度 83.9）。选择分区后，页面会显示实际被替代的球队。
- 比赛先按球队层面的实力与节奏模拟；赛季结束后再根据球员评分与轮换生成个人数据和奖项。快照不会自动更新；重新抓取并生成 `dist/teams.js` 后才会变化。

页面选秀区的“评分来源与口径”面板可直接查看 2K 版本、对手评分口径和数据源；完整公式与边界见 `RATING-SOURCES.md`。

## 个人数据与奖项

赛季模拟结束后，页面会展示你的首发五人常规赛数据：出场、场均时间、得分、篮板、助攻、抢断、盖帽和命中率。

- 你的五人使用所选卡片评分生成数据；其余 29 队以 2026–27 实际场均得分、篮板、助攻、抢断、盖帽为基准，缩放到本次模拟的球队总分和节奏。
- 个人数据是 82 场赛季的模拟产物，不是真实统计，也不代表球员在现实中会打出同样数据。
- **MVP**：综合个人得分、篮板、助攻、抢断、盖帽、球队胜场和个人总评评选。
- **得分王**：全联盟场均得分最高者。
- **DPOY**：综合防守评分、抢断、盖帽、篮板、个人总评和球队胜场评选，其中盖帽与抢断权重最高。
- **FMVP**：从总冠军球队中评选，并生成一轮总决赛场均数据；不保证是常规赛 MVP。
- 奖项使用同一随机种子，和比赛结果一起可复现；同一阵容重新模拟会得到不同的赛季故事。

## 模型边界

所有能力值、巅峰年份及赛果都是游戏设定；现役球员与对手球队数据是项目快照，不是实时数据。对手球队强度只取决于球员评分与轮换，不采用真实战绩强弱。现役能力值根据开季统计映射，并与历史池校准为相近的游戏尺度；样本较小，不能当成官方评分、真实战力或赛季预测。历史池总评来自 2K，但攻防投传板子项是映射值；当最高总评来自只有总评字段的 2K16–2K21 数据时，子项使用同队 2K25 All-Time 卡映射，详见来源说明。

阵容评分 = min(99, 五人卡片总评平均值 + 搭配修正)。卡片总评已经包含个人攻防与投射 / 组织 / 篮板专长，因此不再用五项平均重复压低球星。搭配修正：至少三位投射 85+ 加 2 分，两位 0 分，仅一位扣 2 分，无射手扣 4 分；两位以上组织 85+ 加 1.5 分，无组织点扣 3 分；内线防守 90+ 加 1.5 分，低于 80 扣 2 分。

双方强度差 × 1.45 + 主场 2.6 分 + 标准差 12 的正态随机波动决定分差。替补统一，不模拟伤病。所有球队 82 场、41 主 41 客；自定义平衡赛程不等于真实 NBA 赛程。用户可选择东部或西部，替代该分区现役评分最低的球队。对手球队强度由 2026–27 球员能力值与前 9 人轮换加权换算，比赛节奏由场均得失分换算。排名同胜场按净胜分，再按球队序号。

分区前六直接晋级，7–10 名附加赛决出第七、八种子，随后七场四胜固定对阵树。所有 30 队常规赛、两区附加赛及 15 组系列赛均实际模拟。每次新种子对应新一季。

页面玩法弹窗包含赛制参考链接。球迷作品，与 NBA 及 NBA 2K 无官方关联。
